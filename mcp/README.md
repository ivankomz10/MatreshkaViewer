# MCP для кинетики и вьюера Матрёшки

Сервер MCP, который даёт модели управлять кинетикой Зарядья и рисовать
здание — без окна, в своём процессе. Нужен, чтобы генератор картинок мог сам
проверить форму, поправить её и посмотреть, что вышло.

Рядом два документа **для модели**, не для человека — их надо отдать в
контекст тому чату, который генерирует формы:

- `KINETIC.md` — машина и её пределы: кольца, домкраты, пушеры, наклоны,
  что можно и чего нельзя, формат моторного JSON;
- `VIEWER.md` — экраны здания, камера шоу и что из контента съедают ламели.

## Что чинит

Генератор, который двигает пушеры и не трогает домкраты, делает позы, которые
машина не исполнит: сота поворачивается в зазор между кольцами, а зазор
открывает домкрат. На 1500 сот такая поза даёт тысячу невозможных.

Инструмент `kinetic_fit` берёт желаемую позу и поднимает ровно те домкраты,
которых не хватает, — силуэт остаётся прежним.

## Установка

Нужен интерпретатор вьюера — тот же, что запускает программу из исходников:

```bash
E:\05_Render\Matreshka_Viewer\tool\.venv\Scripts\python.exe -m pip install -r mcp\requirements.txt
```

Если `.venv` рядом с `tool` нет:

```bash
cd E:\05_Render\Matreshka_Viewer\tool
python -m venv .venv
.venv\Scripts\pip install -r requirements.txt
.venv\Scripts\pip install -r ..\mcp\requirements.txt
```

Нужна видеокарта — только для картинок. Пределы, подгонка, ключи, симуляция и
экспорт считаются и без неё.

## Подключение

Подробно, включая настройку чата GPT, — в [SETUP.md](SETUP.md). Коротко:

Транспорт stdio. В конфиге клиента (Claude Desktop, Cursor, свой клиент на
OpenAI SDK — везде одна форма):

```json
{
  "mcpServers": {
    "matreshka": {
      "command": "E:\\05_Render\\Matreshka_Viewer\\tool\\.venv\\Scripts\\python.exe",
      "args": ["E:\\05_Render\\Matreshka_Viewer\\mcp\\server.py"]
    }
  }
}
```

Пути — свои. Сервер сам находит `tool/` на уровень выше себя, так что папку
`mcp` надо держать внутри дерева вьюера.

## Что внутри

| файл | |
|---|---|
| `server.py` | сам сервер: 20 инструментов, stdio |
| `bridge.py` | мост к коду вьюера: пределы, подгонка, проект, рендер |
| `KINETIC.md` | документ для модели: машина и её ограничения |
| `VIEWER.md` | документ для модели: здание, экраны, камера |
| `test_bridge.py` | 27 тестов: каждое число из документов проверено кодом |
| `test_server.py` | 6 тестов: сервер поднимается и отвечает по stdio |
| `SETUP.md` | инструкция по подключению: MCP, клиенты, системный промпт |
| `scratch/` | лог и настройки, чтобы ничего не писалось в `tool/` |


## Коротко о главном

Поза — три поля: `lift` (30 домкратов, целые 0…3), `push` (30×10 пушеров,
0…1), `tilt` (30×50 наклонов, −0.5…0.5, плюс — лицом вниз). Любое из них можно
задать одним числом или одним числом на кольцо.

Путь от силуэта до файла:

```
kinetic_profile   -> вынос пушеров по кольцам
kinetic_auto_tilt -> наклоны вдоль получившейся поверхности
kinetic_fit       -> поднимает домкраты, поза становится исполнимой
kinetic_render    -> посмотреть
kinetic_new / kinetic_key / kinetic_simulate / kinetic_export
```

`kinetic_simulate` важен: машина выбрасывает команду, пришедшую, пока мотор
ещё едет или отдыхает. Ключи встык теряют каждый второй ход. Экспорт по
умолчанию разносит ходы сам.
