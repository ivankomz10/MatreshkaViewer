# Таймлайн вместо строк

Предложение по реализации. Документ описывает, как устроено шоу на площадке,
что из этого нужно повторить в просмотрщике, во что превращается интерфейс и
чего это стоит. Реализации пока нет.

## Зачем

Сейчас источники в просмотрщике — это строки: файл на экран, цепочка файлов
подряд, счётчик повторов у каждой. Это работает, пока файлов два-три, и
перестаёт, когда их двадцать: строки не показывают, **когда** что играет, а
шоу — это в первую очередь расписание. На площадке матрёшкой управляет
проект в TouchDesigner, и там всё уже сделано правильно — таймлайн с
дорожками. Строки надо заменить на то же самое.

## Что лежит в `D:\Content\_SHOW`

40 файлов `.trix` — это JSON. Один файл — одно шоу, то, из чего собирается
проект для запуска. Структура (замерено по всем 40 файлам, 803 видеоклипа,
230 звуковых, 277 кинетических, 119 кью):

```
project   length 79200 кадров, name, version
          79200 при 60 fps = ровно 22 минуты, одинаково во всех 40 файлах
video     три холста: Tiles-pixels (верх), Scene-pixels (низ), Lamel-pixels
          в каждом — клипы по числовому id, id уникальны на весь файл
audio     path, tx, level
jsons     path, tx, prepare_enabled, prepare_offset, prepare_interval
cue       frame, universe, channel, value, level
```

Видеоклип:

```
path                 файл
tx                   кадр таймлайна, с которого он начинается
level                номер дорожки внутри холста
crop_start/_end      подрезка, в кадрах; _end отрицательный
fade_start/_end      затухание, в кадрах; _end отрицательный
loop                 повторять
loop_custom_range    [от, до]
transform            x, y, scale, rotation, flip_x, flip_y, opacity, seamless
```

**Абсолютное размещение, а не цепочка.** `tx` — это место на общем
таймлайне; клипы могут стоять с промежутками и накладываться. Наша модель
«строки подряд» — вырожденный случай этой.

### Что из схемы реально используется

Схема разрешает больше, чем кто-либо применяет. По всем 803 видеоклипам:

| Поле | Использование |
|---|---|
| `tx` | всегда, это основа |
| `level` | 0, 1 и 2 — контент; 3 — всегда ровно один клип на шоу, чёрная подложка |
| `crop` | только `(0, -60)`, 78 раз: секунда с хвоста. С головы — ни разу |
| `fade` | только `(0, -120)` (234 раза) и один `(0, -216)`: две секунды на затухание. С головы — ни разу |
| `loop` | `true` ровно 40 раз — по одному на шоу, и всегда это `black.png` на дорожке 3 |
| `loop_custom_range` | ни разу не отличается от `[0, 100]` |
| `transform` | ни одного значения, отличного от единичного, во всех 40 шоу |
| `prepare_*` у кинетики | ни разу не включено |
| `cue` | universe всегда 2, value всегда 255, level всегда 0 — по сути «кадр + канал» |

Два вывода, которые меняют план.

**Луп на площадке — это не «повтори ролик шесть раз».** Это «держи
подложку всё шоу»: единственное применение на 40 шоу — чёрная картинка под
всем остальным. Кастомный диапазон лупа не использован ни разу. То есть та
работа с лупами, которую я сделал в 0.3 строками, отвечает на вопрос,
которого у production-инструмента нет. Полноценный луп в таймлайне всё равно
нужен (он есть в интерфейсе оригинала, и им когда-нибудь воспользуются), но
он не главный — главное расписание.

**`transform` можно не делать.** Ни одного ненулевого сдвига за 40 шоу.
Читать поле буду, применять — нет; если однажды появится, скажу в лог.

### Сколько слоёв одновременно

Это единственное число, которое решает, сколько придётся менять в рендерере.
Замерено: взял длительности самих файлов и посчитал самую глубокую
одновременность на каждом стыке клипов.

```
Tiles-pixels    3 клипа в 39 шоу из 40
Scene-pixels    2 клипа в 39 шоу из 40
Lamel-pixels    2 клипа в 39 шоу из 40
звук            2 дорожки в 39 шоу из 40
кинетика        2 файла в 37 шоу, 3 в одном
```

Один из трёх на Tiles — всегда чёрная подложка. То есть **два настоящих
ролика плюс заливка**, не больше. Дорожки 0 и 1 чередуются через секцию
(`1100` на 1, `11718` на 0, `37057` на 1, `55441` на 0 …) — это A/B-роллинг:
предыдущая секция ещё затухает своими двумя секундами, следующая уже
началась.

Дорожек, впрочем, три, а не две. Дорожка 2 занята в трёх шоу, и в самом
плотном из них (`LenVokzal-RechVokzal-Kinoport`) секции идут 2 / 1 / 2 — то
есть нулевая и первая в этот момент заняты, и третья дорожка нужна по делу, а
не по случайности. На глубину сборки это не влияет: одновременно всё равно
не больше двух роликов, а третья дорожка — это лишняя строка в интерфейсе.

Кинетика пересекается по-другому: у `jsons` нет `level`, значит разрешать
конфликт дорожками нечем. Перекрытие там — это «объявленная длина» файла,
доезжающая в следующую секцию, а не два одновременно командующих файла.
Семантика для просмотрщика: **действует последний файл, чей `tx` уже
наступил**.

## Два режима

Как просили: простой и таймлайн. Переключатель рядом с режимами отрисовки —
это про то, чем окно управляют, а не про то, что оно рисует.

### Простой

Ровно интерфейс 0.2: по одному файлу на строку, шесть строк, никаких
счётчиков, никаких дополнительных строк, вся панель сворачивается одним
блоком. Всё, что я добавил строками в 0.3 — цепочки, лупы, отдельные
заголовки — из простого режима уходит. Он для «положил три файла, посмотрел».

### Таймлайн

```
┌──────────────────────────────────────────────┬─────────────────┐
│                                              │  Клип           │
│              превью матрёшки                 │                 │
│                                              │  файл           │
│                                              │  кадр начала    │
│                                              │  длина          │
│                                              │  подрезка ↔     │
│                                              │  фейд   ↔       │
│                                              │  луп ▢ / свой   │
│                                              │  дорожка        │
│                                              │  удалить        │
├──────────────────────────────────────────────┴─────────────────┤
│  ⏮ ⏹ ▶ ⏭   00:04:15:28          0 / 79200      22:00.0        │
├────────────────────────────────────────────────────────────────┤
│ Top     ┃▓▓▓▓▓▓▓▁▁▁▁▁▁▁▁▁▁▓▓▓▓▓▓▓▓▓▓▓▓▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁▁ │

│ Lamels  ┃…                                                     │

```

Как в оригинале: превью сверху, дорожки снизу, настройки выбранного клипа
справа. Что отличается — у нас превью это геометрия здания, а не плоский
холст, и режимы отрисовки (Превью / Flat / ReBake / Inspection) остаются как
есть: таймлайн говорит, *что* играет в этот кадр, а режим — *как* это
показать.

Дорожки: три на каждый экран плюс подложка, две на звук, одна на кинетику,
одна на кью. Пустые дорожки прятать — в большинстве шоу заняты 0 и 1. Клип —
прямоугольник с именем файла; затухания нарисовать скосом на конце, подрезку
— штриховкой за краем. Перетаскивание по горизонтали двигает `tx`, за край —
подрезает, между дорожками — меняет `level`.

Кью — только метки и список. В сеть просмотрщик не шлёт ничего и не должен:
он не подключён к оборудованию.

## Чего это стоит

Разбито по слоям снизу вверх. Первые три пункта — настоящая работа, дальше
интерфейс.

### 1. `player.Track` вместо `player.Chain`

Цепочка, которую я написал в 0.3, — это ровно то же самое с одним
ограничением: клипы лежат подряд без промежутков. Убрать ограничение —
значит заменить «начало = сумма предыдущих» на «начало = `tx`» и разрешить
промежутки (в промежутке дорожка не даёт кадра вовсе). Всё сложное в
`Chain` — ленивое открытие, подготовка следующего клипа за секунду до стыка,
переклейка номеров кадров на общую сетку, пересборка поверхности под другой
формат — переносится как есть. Это эволюция файла, а не переписывание.

Плюс `Stack` — несколько `Track` на один экран, отдающих кадры по уровням.

### 2. Сборка экрана из слоёв

Сейчас на экран биндится одна видеотекстура (`solid.set_video`). Нужно
сначала собрать экран из своих слоёв в отдельную текстуру, потом отдать её
геометрии. Через `Painter`, который уже умеет рисовать `Screen` в цель с
режимами альфы, — то есть новый проход, а не новый шейдер.

Цена: по одной полноразмерной RGBA-текстуре на экран (4608×1584 — это 29 МБ;
на три экрана ~50 МБ) и по проходу на слой. Это же заодно ставит на место
накладку Frame, которая сейчас особый случай в шейдере.

Затухание и подрезка считаются здесь: затухание — множитель на альфу слоя
(он уже есть, `set_video_opacity`), подрезка — просто смещение кадра.

### 3. Два звука

`sound.py` читает один WAV и отдаёт часы. Нужно складывать два чтения в
один вывод; часы по-прежнему берутся с вывода, так что снаружи ничего не
меняется.

### 4. Чтение `.trix`

Только чтение, как решили. Открыть шоу из `_SHOW`, разложить по дорожкам,
показать. Правки живут в своём файле рядом (`*.viewer.json`), шоу не
трогается — испортить то, что пойдёт на площадку, из просмотрщика нельзя.

Отсутствующие файлы — обычное дело (из 40 шоу 8 видео и 7 звуков лежат на
дисках, которых тут нет). Клип с ненайденным файлом рисуется на дорожке
красным и не мешает смотреть остальное.

### 5. Виджет дорожек

Самая большая часть интерфейса, и здесь я предлагаю не экономить: свой
виджет с рисованием, а не сборка из кнопок. Прокрутка и зум по времени,
выбор клипа, перетаскивание, привязка к границам соседей и к кадру.

### 6. Инспектор

Панель справа: путь, кадр начала, длина, подрезка, фейд, луп, дорожка,
удалить. Плюс, чего нет в оригинале и что стоит добавить: **разрешение и
кодек клипа** — это то, за чем в просмотрщик и приходят.

### Что уходит

Строки-цепочки, счётчики повторов, кнопка «столько же по колонке», отдельные
заголовки на каждый экран. Простой режим возвращается к шести строкам и
одному блоку сворачивания; всё расписание переезжает в таймлайн. `Chain`
остаётся, но как `Track`.

## Порядок работ

1. `Track`/`Stack` в `player.py`, с тестами на промежутки и перекрытия.
2. Сборка экрана из слоёв в отдельную текстуру; проверка, что один слой
   даёт побитово ту же картинку, что и прямой бинд сейчас.
3. Чтение `.trix` + модель шоу, без интерфейса: тест «открыли 40 шоу, у
   всех сошлась длина, все клипы разложились».
4. Виджет дорожек, только чтение и выбор.
5. Инспектор и правки (перетаскивание, подрезка, фейд, луп).
6. Два звука.
7. Переключатель режимов и возврат простого режима к шести строкам.

Шаги 1–3 проверяются тихой пачкой без участия рук. Шаги 4–5 — то, где
понадобится шумная.

## Открытые вопросы

- **Какой уровень спереди.** `black.png` всегда на 3, контент на 0 и 1, так
  что похоже, что больший номер — дальше. Проверить на оригинале, поставив
  два клипа с прозрачностью друг на друга: угадывать здесь нельзя, ошибка
  переворачивает все стыки.
- **`crop_start` и `fade_start`.** В интерфейсе оригинала они есть, в файлах
  не использованы ни разу. Делать симметрично или только хвост — решить,
  когда дойдём до инспектора.
