# Таймлайн вместо строк

Предложение по реализации. Документ описывает, как устроено шоу на площадке,
что из этого нужно повторить в просмотрщике, во что превращается интерфейс и
чего это стоит. Реализации пока нет.

## Зачем

Сейчас источники в просмотрщике — это строки: файл на экран, цепочка файлов
подряд, счётчик повторов у каждой. Это работает, пока файлов два-три, и
перестаёт, когда их двадцать: строки не показывают, **когда** что играет, а
шоу — это в первую очередь расписание. На площадке матрёшкой управляет
проект в TouchDesigner, и там всё уже сделано правильно — таймлайн с
дорожками. Строки надо заменить на то же самое.

## Что лежит в `D:\Content\_SHOW`

40 файлов `.trix` — это JSON. Один файл — одно шоу, то, из чего собирается
проект для запуска. Структура (замерено по всем 40 файлам, 803 видеоклипа,
230 звуковых, 277 кинетических, 119 кью):

```
project   length 79200 кадров, name, version
          79200 при 60 fps = ровно 22 минуты, одинаково во всех 40 файлах
video     три холста: Tiles-pixels (верх), Scene-pixels (низ), Lamel-pixels
          в каждом — клипы по числовому id, id уникальны на весь файл
audio     path, tx, level
jsons     path, tx, prepare_enabled, prepare_offset, prepare_interval
cue       frame, universe, channel, value, level
```

Видеоклип:

```
path                 файл
tx                   кадр таймлайна, с которого он начинается
level                номер дорожки внутри холста
crop_start/_end      подрезка, в кадрах; _end отрицательный
fade_start/_end      затухание, в кадрах; _end отрицательный
loop                 повторять
loop_custom_range    [от, до]
transform            x, y, scale, rotation, flip_x, flip_y, opacity, seamless
```

**Абсолютное размещение, а не цепочка.** `tx` — это место на общем
таймлайне; клипы могут стоять с промежутками и накладываться. Наша модель
«строки подряд» — вырожденный случай этой.

### Что из схемы реально используется

Схема разрешает больше, чем кто-либо применяет. По всем 803 видеоклипам:

| Поле | Использование |
|---|---|
| `tx` | всегда, это основа |
| `level` | 0, 1 и 2 — контент; 3 — всегда ровно один клип на шоу, чёрная подложка |
| `crop` | только `(0, -60)`, 78 раз: секунда с хвоста. С головы — ни разу |
| `fade` | только `(0, -120)` (234 раза) и один `(0, -216)`: две секунды на затухание. С головы — ни разу |
| `loop` | `true` ровно 40 раз — по одному на шоу, и всегда это `black.png` на дорожке 3 |
| `loop_custom_range` | ни разу не отличается от `[0, 100]` |
| `transform` | ни одного значения, отличного от единичного, во всех 40 шоу |
| `prepare_*` у кинетики | ни разу не включено |
| `cue` | universe всегда 2, value всегда 255, level всегда 0 — по сути «кадр + канал» |

Два вывода, которые меняют план.

**Луп на площадке — это не «повтори ролик шесть раз».** Это «держи
подложку всё шоу»: единственное применение на 40 шоу — чёрная картинка под
всем остальным. Кастомный диапазон лупа не использован ни разу. То есть та
работа с лупами, которую я сделал в 0.3 строками, отвечает на вопрос,
которого у production-инструмента нет. Полноценный луп в таймлайне всё равно
нужен (он есть в интерфейсе оригинала, и им когда-нибудь воспользуются), но
он не главный — главное расписание.

**`transform` можно не делать.** Ни одного ненулевого сдвига за 40 шоу.
Читать поле буду, применять — нет; если однажды появится, скажу в лог.

### Сколько слоёв одновременно

Это единственное число, которое решает, сколько придётся менять в рендерере.
Замерено: взял длительности самих файлов и посчитал самую глубокую
одновременность на каждом стыке клипов.

```
Tiles-pixels    3 клипа в 39 шоу из 40
Scene-pixels    2 клипа в 39 шоу из 40
Lamel-pixels    2 клипа в 39 шоу из 40
звук            2 дорожки в 39 шоу из 40
кинетика        2 файла в 37 шоу, 3 в одном
```

Один из трёх на Tiles — всегда чёрная подложка. То есть **два настоящих
ролика плюс заливка**, не больше. Дорожки 0 и 1 чередуются через секцию
(`1100` на 1, `11718` на 0, `37057` на 1, `55441` на 0 …) — это A/B-роллинг:
предыдущая секция ещё затухает своими двумя секундами, следующая уже
началась.

Дорожек, впрочем, три, а не две. Дорожка 2 занята в трёх шоу, и в самом
плотном из них (`LenVokzal-RechVokzal-Kinoport`) секции идут 2 / 1 / 2 — то
есть нулевая и первая в этот момент заняты, и третья дорожка нужна по делу, а
не по случайности. На глубину сборки это не влияет: одновременно всё равно
не больше двух роликов, а третья дорожка — это лишняя строка в интерфейсе.

### Слои складываются, а не накладываются

`level` — не порядок перекрытия. Это выяснилось в самом приложении, и это
главное, что стоило туда пойти.

Замеры, каждый из которых легко повторить.

**Первый.** В открытом шоу на верхнем экране есть ровно одно окно, где два
настоящих ролика живут одновременно: кадры **11718..11840**, ровно две
секунды. Уходящий `kinetic_screen_out` (уровень 1) держит яркость 66.4 до
последнего своего кадра — по контенту он не темнеет вообще, затемнение делает
только `fade_end: -120`. Входящий `RusDay_SHOW_Top` (уровень 0) в этом окне
**чёрный по контенту** и `YCoCg_DXT5`, то есть без альфы, непрозрачный.

Поставил плейхед на кадр 11742 и посмотрел: верхний экран показывает матрёшку
на шестиугольниках — уходящий клип уровня 1. Непрозрачный чёрный клип уровня 0
его не перекрыл.

**Второй.** `black.png` (уровень 3, `loop: true`, живёт всё шоу) — картинка
4608×1584 с альфой **255 во всех пикселях**. Полностью непрозрачная.

Дальше арифметика. Если спереди меньший номер — непрозрачный чёрный уровень 0
обязан был скрыть матрёшку на кадре 11742. Не скрыл. Если спереди больший
номер — непрозрачная чёрная подложка уровня 3 обязана была сделать всё шоу
чёрным с кадра 800. Не сделала. **Ни один порядок «alpha over» не объясняет
оба замера сразу.**

Объясняет их сложение: чёрное не вносит вклада. Тогда непрозрачная подложка
безвредна, чёрная фаза входящего клипа не перекрывает уходящий, а `level`
оказывается просто номером дорожки в интерфейсе, а не глубиной.

И шоу под это написано. Все 40 файлов: **входящий клип всегда открывается из
чёрного** — `RusDay_SHOW_Top` поднимается с 0 до 138 за 260 кадров,
`7Sisters_Top` держит ноль первые 58 кадров. Двух ярких слоёв одновременно не
бывает нигде, поэтому сложение никогда не пересвечивает.

Для нас это **упрощение**: складывать слои дешевле, чем накладывать по альфе,
и порядок дорожек можно не хранить вовсе.

Кинетика пересекается по-другому: у `jsons` нет `level`, значит разрешать
конфликт дорожками нечем. Перекрытие там — это «объявленная длина» файла,
доезжающая в следующую секцию, а не два одновременно командующих файла.
Семантика для просмотрщика: **действует последний файл, чей `tx` уже
наступил**.

### Что показал сам интерфейс

Вещи, которых в файлах не видно.

**Панель клипа справа: `Name`, `Lock`, `ID`, `Fade`, `Crop`, `Loop`,
`Custom Loop`, `Start Frame`, `Length`, `Canvas`, `DELETE`.** И `Fade`, и
`Crop` — по **одному** полю, не по паре. В JSON это пары
(`fade_start`/`fade_end`, `crop_start`/`crop_end`), и теперь понятно, почему
во всех 803 клипах начала ровно нулевые: **их нечем задать**, в редакторе нет
такого поля. То есть подрезка и фейд там по смыслу «с хвоста», а поля начала
существуют только в формате.

**Поля `level` в панели нет.** Уровень задаётся тем, на какой строке лежит
клип. Причём дорожки рисуются не стопкой, а **лестницей**: высота ступени —
номер уровня, и по ней видно, как секции чередуют 1 / 0 / 1 / 0. Уровень 3 в
лестнице не участвует вовсе — подложка не считается дорожкой.

**Вкладки `Media` / `Audio` / `Kinetic` / `Cue` — это четыре раздела JSON, но
не список содержимого.** Media, Audio и Kinetic пустые: это «входящая
корзина», куда кладут новый файл. Список клипов живёт только на таймлайне.
Заполнена только `Cue` — таблица `Frame / Universe / Channel / Value`, её
набирают руками.

**Плейхед тащат за его же табличку с номером кадра.** Номер не набирается с
клавиатуры, щелчок по линейке плейхед не двигает. Мелочь, но в нашем виджете
стоит сделать все три способа — они все ожидаемы.

**Под таймкодом кнопки `LOOP` и `RENDER`** — приложение само умеет писать
файл. В тулбаре сверху `Black Content`, `Show Mask`, `Perspective` и три
кнопки `S` / `T` / `L` — по холсту на кнопку, то есть превью умеет
показывать один экран плоско. У нас это уже есть, и называется Flat.

**Правый край таймлайна — `00:22:00:00`**, и длина проекта неизменна во всех
40 шоу. Длина — свойство слота, а не содержимого.


## Три уровня

Главное требование: по умолчанию — быстрый предпросмотр результата, а таймлайн,
инспектор и прочее — расширенный функционал для тех, кому он нужен.

```
Просмотр        по умолчанию. Шесть строк, один блок, ползунок. Как 0.2
Шоу             таймлайн, открыт на чтение: смотреть .trix, лупы, рендер
  └ Редактор    то же, но отперто: правка шоу и сборка шоу с нуля
```

Имена — про задачу, а не про виджет. «Превью» остаётся режимом *отрисовки*
(здание через камеру из файла) наравне с Flat, ReBake и Inspection, и
переименовывать его второй раз за две недели незачем: рабочий режим говорит,
*чем* окно управляют, режим отрисовки — *как* это показано.

### Просмотр

Ровно интерфейс 0.2: по одному файлу на строку — Top, Bottom, Lamels, Frame,
Sound, Kinetic — вся панель сворачивается одним блоком, внизу обычный ползунок
времени. Для «положил три файла, посмотрел, отрендерил».

Из 0.3 отсюда уходит всё про расписание: цепочки строк, счётчики повторов,
кнопка «столько же по колонке», отдельные заголовки на каждый экран, галка
«Лупы». Их работу делает Шоу.

Frame живёт только здесь. В `.trix` накладки нет, и в Шоу она была бы
вещью, которой нет на площадке.

### Шоу

Прототип, вставленный вокруг настоящего превью:

```
┌────────────────────────────────────────────┬──────────────┐
│ Просмотр|Шоу  ✎Редактор   имя проекта      │              │
│ отрисовка ▾ · Body Shell … Match Alpha     │  Лупы        │
├────────────────────────────────────────────┤  с [800]     │
│                                            │  по [1099]   │
│         превью здания (как сейчас)         │  + − клип    │
│                                     ? клав.│  из файла    │
│                                            │──────────────│
╞══════════ перетаскиваемая граница ═════════╡  Клип        │
│ LOOP ▕▔▔▔▔▔▔▔▔▔ лупы ▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▔▕ 🔒 │  кадр, фейд, │
│      линейка / плейхед                     │  подрезка …  │
│ Cue · Kinetic · Top ×3 · Bottom ×3 ·       │              │
│ Lamels ×3 · Sound ×2                       │  файл —      │
│                                            │  полный путь │
├────────────────────────────────────────────┴──────────────┤
│ транспорт                              экспорт / рендер   │
└───────────────────────────────────────────────────────────┘
```

Открыто на чтение. Дорожки не тащатся, поля инспектора только показывают,
лупы не рисуются — то, что пойдёт на площадку, из просмотрщика случайно не
сдвинуть.

Что перенесено из прототипа как проверенное:

- Дорожка на уровень, сверху вниз Cue, Kinetic, Top, Bottom, Lamels, Sound;
  по три уровня на экран, два на звук. Чёрная подложка — не клип: подложку
  выбирает сам просмотрщик, Calibration или Black.
- Лупы читаются из файла — зацикленный клип от своего `tx` до прихода
  следующего, во всех 40 шоу это 800..1099 — и их может быть несколько.
- LOOP стоит в голове лупной полосы и по умолчанию погашен. Плейхед
  пересекает начало лупа слева — кнопка зажигается сама, луп держит.
  Гасит её только рука, и из того лупа, из которого отпустили, плейхед
  выходит свободно. Старт внутри лупа его не включает.
- Замок на правом конце лупной полосы, точные кадры — числами в правом
  столбце: на 22 минутах один пиксель — это 56 кадров.
- Мышь: левая — выбор и перетаскивание, пустое место снимает выделение и
  никогда не двигает плейхед; правая — прокрутка; средняя — плейхед сюда;
  колесо — зум. Сам плейхед берётся только за линейку.
- Клавиши: пробел, стрелки по кадру и с Shift по секунде, `I`/`O` на края
  клипа, `[`/`]` — клип слева и справа от плейхеда, `L` — луп, `Shift+L` —
  луп на весь клип, `K` — замок, `Home`/`End`, `F` — вся длина. Подсказка —
  поверх превью по `?`, а не постоянно, как в прототипе.
- Фейды — заливка плюс засечка там, где фейд начинается, и линия спада;
  подрезка — засечка на краю. Кинетика продлена на доезд моторов и эта часть
  заштрихована: файл там кончился, а соты ещё едут.
- Путь к файлу в инспекторе — целиком, отдельным блоком, выделяемый.

Граница между превью и дорожками перетаскивается: тринадцать дорожек — это
около 330 пикселей, и на небольшом мониторе картинке надо уметь вернуть
высоту.

Рендер проигрывает каждый луп один раз — как будто оператор отпускал каждое
ожидание сразу после первого прохода. Длина файла предсказуема, ожидания
видны и не растягиваются; для 800..1099 это пять секунд чёрного перед
стартом.

### Редактор

Переключатель «✎ Редактор» в Шоу отпирает всё разом: дорожки тащатся, поля
инспектора пишут в клип, лупы рисуются. Замок на лупной полосе остаётся
внутри редактора как отдельная защита — лупы из файла сломать проще всего.

- **Правка шоу из `.trix`** — всё, что есть в прототипе.
- **Сборка шоу с нуля.** Файл бросается из проводника прямо на дорожку, в то
  место, куда его отпустили; клип удаляется; кью добавляется кнопкой, потому
  что это не файл. Отдельной «корзины» Media / Audio / Kinetic, как в
  оригинале, нет — там она пустая и лишний шаг.
- **Ctrl+Z / Ctrl+Y.** Редактор шоу без отмены опасен, это в объёме без
  вопроса.
- **Имя проекта** — поле наверху: читается из `project.name` уже в Шоу,
  правится в редакторе.
- **Рабочий файл.** Редактор хранит свою версию JSON-ом в отдельной папке
  черновиков, `drafts\` рядом с программой, и пишет его сам на каждую
  правку — с задержкой после последнего движения, как `settings.json`. Так
  правки переживают закрытие и падение. Открыл тот же `.trix` снова —
  предлагается продолжить с черновика. Рядом с программой, а не в системном
  `%TEMP%`: Windows чистит `%TEMP%` сама, а рабочий файл должен пережить
  неделю.
- **Финал** — экспорт в `.trix`: новой версией рядом с исходником (`-v002`
  возле `-v001`) или под новым именем, исходник не трогается никогда. Это
  отдельная задача, после всего остального; до неё в `_SHOW` ничего не
  пишется.

### Как попадают из одного в другой

По тому, что открыли, и переключатель наверху всегда под рукой.

- Бросили ролики на строки — Просмотр. Открыли `.trix` — сразу Шоу.
- Просмотр → Шоу без потерь: файлы строк становятся клипами на нулевом кадре.
- Шоу → Просмотр — только если шоу помещается в «один клип на экран».
  Иначе Просмотр показывает то, что стоит под плейхедом, и предлагает
  остаться в Шоу.
- Настройки 0.3 с цепочками открываются в Шоу: клипы встают друг за другом,
  счётчик повторов разворачивается в столько же копий подряд — длина та же,
  что была. В лог пишется, что было развёрнуто.

## Движок

Один на все три уровня: под капотом всегда шоу. Просмотр — это шоу, где на
каждом экране один клип с `tx = 0` и лупов нет, так что второго пути
проигрывания не появляется, и всё, что починено в движке, работает везде.

- **`player.Track` вместо `player.Chain`.** Замена «начало = сумма
  предыдущих» на «начало = `tx`» и разрешённые промежутки. Всё трудное в
  `Chain` — ленивое открытие, подготовка следующего клипа за секунду до
  стыка, переклейка номеров кадров на общую сетку, пересборка поверхности
  под другой формат — переносится как есть.
- **`Stack`** — дорожки одного экрана. Экран собирается из своих слоёв в
  отдельную текстуру **сложением** и только потом идёт на геометрию. Порядок
  дорожек не хранится: он не задаёт перекрытия.
- **Два звука** складываются в `sound.py`; часы по-прежнему берутся с вывода.
- **`show.py`** — модель шоу и чтение `.trix`: лупы из файла, доезд моторов
  (BrendMT_1_of_2 продлевается на 154 кадра, 7Sisters на 125), ненайденный
  файл — красный клип, а не отказ открыть шоу.
- **Часы — дробные.** Урок прототипа: целочисленный кадр терял 0.96 кадра на
  каждом шестнадцатимиллисекундном тике, и шестьдесят кадров в секунду
  превращались в три. Настоящий `Clock` так и устроен — `raw` не
  округляется, — это надо сохранить при переделке.
- **Луп ищется там, где плейхед сейчас**, а не там, куда он едет, — иначе
  один тик перешагивает дальний край, и снаружи ловить уже нечем.

## Порядок работ

Каждый этап — отдельный выпуск, который работает сам по себе.

1. **Движок без интерфейса.** `show.py`, `Track`/`Stack`, сборка экрана
   сложением, два звука. Проверяется тихой пачкой: 40 шоу читаются и у всех
   сходится длина; лупы 800..1099 во всех; один слой побитово равен прямому
   бинду, как сейчас; доезд BrendMT +154.
2. **Просмотр на новом движке.** Строки 0.3 откатываются к 0.2. Ворота —
   все нынешние тихие тесты зелёные; то, что было про цепочки и счётчики,
   переезжает в тесты Шоу.
3. **Шоу, только чтение.** Дорожки, лупная полоса и правый столбец из
   прототипа, переключатель Просмотр/Шоу, открытие `.trix`, граница-сплиттер,
   подсказка по `?`, рендер с лупами по разу. Здесь понадобится шумная пачка.
4. **Редактор.** Переключатель, правки, бросание файлов на дорожку, удаление,
   кью кнопкой, отмена, имя проекта, черновик с автосохранением.
5. **Потом, отдельно — экспорт в `.trix`.** Новой версией или под новым
   именем, с именем проекта в `project.name`, и прогон всех 40 шоу
   «прочитал → записал → совпало» до того, как хоть один файл уйдёт на
   площадку.

## Риски

- **Память на открытые ролики.** `Chain` держит открытыми до трёх клипов на
  дорожку. Три дорожки на экран, три экрана — до 27 потоков, а буферы одного
  HAP Q Alpha 4608×1584 — около 30 МБ: под гигабайт. На дорожку нужно два
  (играющий и следующий), и замерить до того, как это станет жалобой.
- **Рендер всего шоу** — 79 200 кадров, 22 минуты. Сколько это идёт на
  RTX 3080 и на маке, надо узнать на первом же этапе Шоу, а не на площадке.
- **Черновик и исходник разошлись.** Если `.trix` поменяли после того, как
  начат черновик, редактор должен сказать об этом, а не молча показывать
  старое. Черновик помнит, с какого файла и какой его версии начат.

## Прототип

Ветка `proto/timeline`, папка `tool/proto_timeline` — выбрасываемый код, в
основную программу не вливается, а переписывается по этому документу:

```bash
git checkout proto/timeline
```

```bash
tool\proto_timeline\run.bat
```

Варианты B («лестница», дорожка на экран) и C (таблица секций) отброшены по
ходу; остался один — дорожка на уровень, всё про лупы и клип в правом
столбце. В шоу прототип ничего не пишет: клип тащится в памяти и при
перезагрузке возвращается на место.

## Потом, отдельными задачами

- Экспорт в `.trix` — этап 5 выше.
- `transform` клипа: читается, не применяется — во всех 40 шоу он
  единичный. Если однажды появится, говорим в лог.
- `prepare_*` у кинетики — ни разу не включено ни в одном шоу.
