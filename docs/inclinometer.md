# Симулятор инклинометра кинетической части

Предложение по реализации. Документ описывает, что показывать, откуда брать
данные, какие есть варианты по глубине физики и визуализации, и как это ложится
на текущую архитектуру. Реализации пока нет — это проект и варианты.

## Зачем

Кинетическая партитура (motor-JSON) двигает 1500 сот верхнего экрана: домкраты
поднимают кольца, пушеры выдвигают группы сот радиально, тилты качают отдельные
соты. Инклинометр нужен как **диагностика физичности и безопасности** такой
партитуры: показать, насколько конструкция кренится от перераспределения массы и
не накапливает ли опасную раскачку/кручение — например, когда экраны выдвигаются
по кругу по очереди.

## Что меряем

- **Наклон оси от вертикали** — две компоненты (по X и по Y), либо «величина +
  азимут». Это и есть показание инклинометра.
- **Кручение вокруг вертикали (Z)** — отдельная величина. Именно она
  «накапливается», когда выдвижение идёт волной по кольцу.

Два источника наклона, которые полезно разделять:

1. **Статический (перераспределение массы).** Соты выдвигаются/поднимаются/
   качаются. Осесимметричное движение — центр масс (ЦМ) на оси, крена нет.
   Асимметричное (одна сторона, или бегущая волна) — ЦМ уходит вбок →
   опрокидывающий момент → крен.
2. **Динамический (инерция).** Движущаяся масса имеет импульс. Пушеры,
   срабатывающие по очереди по кругу, дают «бегущую» силовую картину →
   суммарный момент вокруг Z и раскачку. Высокая конструкция на основании
   отвечает как задемпфированный маятник: реакция запаздывает, идёт с перелётом
   и **накапливается** при круговой последовательности.

## Ключевой архитектурный момент

Сейчас кинетика **без состояния**: положение соты — чистая функция таймлайна
(`kinetic.transforms(..., frame, much)` в `tool/kinetic.py`), между кадрами
ничего не переносится. «Накопление инерции» по природе с состоянием (интеграл по
времени). Но весь план моторов известен заранее из JSON, поэтому динамику можно
**посчитать один раз детерминированно** при загрузке файла (один проход по
кадрам), а на отрисовке — просто читать по `Motors.index_at(seconds)`. Так
свойство «функция таймлайна» сохраняется, перемотка и рендер остаются точными.

## Откуда берутся данные (в основном уже есть)

- **Позиции 1500 сот** в любой кадр — `kinetic.transforms(self.cell_at,
  self.cell_is, motors, frame, much)`; центры и адреса — `self.cell_at`,
  `self.cell_is` (см. `_load_motors`/`_move_screens` в `tool/main.py`).
- **Скорости/ускорения** — не гоняя матрицы: продифференцировать уже
  семплированные кривые моторов (`Motors.tilt/pusher/jack`, массивы по кадрам)
  через `np.gradient` по оси кадров, один раз. Дёшево.
- **Масса** — на соту (равномерно или ∝ площади ячейки) + большая «неподвижная»
  масса навеса/основания на оси, чтобы относительное смещение ЦМ было в реальном
  масштабе и с правильным направлением.

## Варианты по глубине физики

### A. Кинематический инклинометр по ЦМ (минимум, без состояния)
Каждый кадр считаем горизонтальное смещение ЦМ подвижных сот от оси → стрелка/
пузырёк: азимут = направление смещения, величина ∝ смещению; вертикальный сдвиг
ЦМ (домкраты) — как плечо момента.
- **Плюсы:** тривиально, детерминированно, ~микросекунды.
- **Минусы:** только статический дисбаланс; круговая волна даст просто
  вращающуюся точку, без «накопления».

### B. Статический крен через жёсткость (A + калибровка в градусы)
Конструкция как жёсткое тело на вращательной пружине у основания: крен
`θ = M / k`, где `M = g · (смещение ЦМ) · масса` — опрокидывающий момент, `k` —
жёсткость основания.
- **Плюсы:** показания в реальных градусах.
- **Минусы:** всё ещё статика, без раскачки.

### C. Предрассчитанная динамика (рекомендуется для «инерции/накопления»)
Модель — обратный маятник с 2–3 степенями свободы: наклон вокруг X и Y +
кручение вокруг Z, с моментом инерции `I`, жёсткостью `k`, демпфированием `c`.
Возбуждение — реактивные моменты от ускоряющихся сот:
`M(t) = Σ rᵢ × (−mᵢ · aᵢ)`. Интегрируем `I·θ'' + c·θ' + k·θ = M(t)` один раз по
всему таймлайну → ряды наклона и кручения.
- **Плюсы:** видно запаздывание, перелёт, резонанс и эффект круговой волны;
  ровно здесь «накапливается» момент вокруг оси.
- **Минусы:** нужны параметры `I, k, c` (оценить из габаритов/массы или вынести
  в настройки), больше кода.

### D. Полноценный многотельник/МКЭ
Избыточно для превью-инструмента. Упомянуто, чтобы отбросить.

## Про «по кругу по очереди» отдельно

Считать чистый угловой момент вокруг вертикали
`L_z = Σ mᵢ (rᵢ × vᵢ)_z`. Волна пушеров/тилтов по кольцу даёт ненулевой
циркулирующий `L_z`, который растёт по мере подключения сот — это и есть
индикатор накопленной угловой инерции; его же удобно показывать стрелкой-
«закруткой».

## Как показывать (можно комбинировать)

1. **Пузырьковый уровень** — точка в круге, цвет по величине, кольцо «peak-hold».
2. **Авиагоризонт** (pitch/roll) — привычно читается как «завал».
3. **Двойной прибор** — крен (величина + азимут) и кручение (загнутая стрелка +
   число `L_z`).
4. **Полоска-трасса под картинкой** — наклон/кручение во времени, синхронно с
   плейхедом: лучше всего видно накопление за сцену.
5. **В 3D-сцене** — вектор наклона/отвес на вершине конструкции.

Рекомендация: компактный прибор-оверлей (п. 3) + опциональная трасса (п. 4).

## Куда встраивается

- Оверлей-виджет, как существующие кнопки/подписи, через `_lay_overlays` в
  `tool/main.py`; кнопка-тумблер; показывать в `Превью`/`Inspection`, когда
  загружен motor-JSON.
- Предрасчёт (B/C) — в `_load_motors`; пересчёт при смене `much` (усиление
  движения уже есть) и параметров `k/c/массы`.
- Значения — в массивы `frames × (наклонX, наклонY, L_z, …)`; на отрисовке
  лукап по `Motors.index_at(seconds)`.

## Проверка

Синтетические motor-JSON:
1. полностью симметричное выдвижение → крен ≈ 0;
2. односторонний пушер → устойчивый крен в известную сторону;
3. круговая волна → нарастающий `L_z` и раскачка.

Сверять с посчитанным вручную ЦМ/моментом.

## Этапы

1. **A/B** — дешёвый и сразу полезный статический инклинометр по ЦМ (кнопка +
   прибор).
2. **C** — режим «инерция»: предрассчитанная динамика для крена и кручения, с
   трассой во времени. Общий расчёт ЦМ/сил переиспользуется из этапа 1.

## Открытые вопросы

- Глубина физики на старте: A/B или сразу C?
- Параметры конструкции (масса подвижной части, жёсткость `k`, демпфирование
  `c`) — задать оценкой из габаритов или оставить настраиваемыми?
- Набор визуализации: только прибор-оверлей или сразу с трассой во времени?
- Единицы показаний: условные (смещение ЦМ) или калиброванные градусы (нужна
  оценка `k`)?
